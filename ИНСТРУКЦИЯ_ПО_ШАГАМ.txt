ПОШАГОВАЯ ИНСТРУКЦИЯ
Тема: Подготовка веб-проекта к размещению на GitHub

ВАЖНО:
1. Распакуйте ZIP-архив.
2. Не удаляйте файлы index.html, style.css, .gitignore и README.md.
3. Файл test.log нужно создать на шаге 6 — он предназначен для проверки .gitignore.

ШАГ 1. Откройте проект
- Распакуйте папку github-ready-project в удобное место, например на Рабочий стол.
- Откройте Visual Studio Code.
- Выберите «Файл → Открыть папку» и укажите github-ready-project.

ШАГ 2. Проверьте сайт
- Откройте index.html в браузере двойным щелчком.
- Убедитесь, что видны заголовок, описание и список работ.

ШАГ 3. Откройте терминал в папке проекта
- В VS Code выберите «Терминал → Создать терминал».
- Проверьте, что терминал открыт именно в папке github-ready-project.
- Введите:
  git init
- Нажмите Enter.
- Затем введите:
  git status
- Нажмите Enter и сделайте скриншот результата.

Если Git пишет, что репозиторий уже существует, это нормально — переходите дальше.

ШАГ 4. Создайте test.log
- В VS Code создайте новый файл с точным именем test.log в корне проекта.
- Оставьте его пустым.
- В терминале выполните:
  git status
- Файл test.log не должен отображаться как обычный неотслеживаемый файл.

ШАГ 5. Проверьте правило игнорирования
- Введите:
  git check-ignore -v test.log
- Нажмите Enter.
- Должна появиться строка, в которой указаны .gitignore и правило *.log.
- Сделайте скриншот результата.

ШАГ 6. Добавьте файлы в Git
- Введите:
  git add .
- Затем введите:
  git status
- Убедитесь, что среди подготовленных файлов есть:
  index.html, style.css, .gitignore, README.md.
- test.log не должен добавляться.

ШАГ 7. Создайте коммит
- Введите:
  git commit -m "Подготовлен проект для размещения на GitHub"
- Нажмите Enter.

Если появится ошибка, что не настроены имя или электронная почта, введите команды со своими данными:
  git config --global user.name "Ваше имя"
  git config --global user.email "ваша-почта@example.com"

После настройки повторите команду git commit.
Не используйте выдуманную почту, если преподаватель требует ваши реальные настройки Git.

ШАГ 8. Проверьте историю
- Введите:
  git log --oneline
- Должен появиться коммит с сообщением «Подготовлен проект для размещения на GitHub».
- Сделайте скриншот результата.

ШАГ 9. Сделайте итоговые скриншоты
Нужно подготовить:
1. Результат команды git status.
2. Результат команды git check-ignore -v test.log.
3. Результат команды git log --oneline.
4. По возможности — страницу сайта в браузере.

ШАГ 10. Ответы на итоговые вопросы
1. Какие файлы войдут в репозиторий?
   Ответ: index.html, style.css, .gitignore и README.md. Файл test.log игнорируется.
2. Почему файл test.log игнорируется?
   Ответ: в .gitignore есть правило *.log.
3. Какую информацию содержит README?
   Ответ: описание проекта, технологии, структуру файлов и инструкцию по запуску.
4. Какие данные нельзя публиковать в открытом репозитории?
   Ответ: пароли, токены доступа, приватные ключи, конфиденциальные документы и личные данные.
5. Готов ли проект к размещению на GitHub?
   Ответ: да, если все нужные файлы присутствуют, .gitignore работает, README заполнен, секретных данных нет и создан коммит.

СПИСОК КОМАНД ПО ПОРЯДКУ
git init
git status
git check-ignore -v test.log
git add .
git status
git commit -m "Подготовлен проект для размещения на GitHub"
git log --oneline

Примечание: это задание требует подготовить локальный репозиторий. Загружать проект на сайт GitHub нужно только если преподаватель отдельно попросит.
